# Persistent real-board I2S diagnostic — 2026-09-18

Result: diagnostic firmware built, flashed, and left running. Eight one-second
sample windows (384,000 stereo frames) showed varying samples on both channels
and zero nonzero-padding words. The old constant -1 observation did not recur
in this capture. This is evidence of live data, not calibrated ADC/RX
performance or verified DMA continuity. Physical I2S clocks still await scope
confirmation by the user.

## User observations before this change

- CLK0 was observed at 14.075 MHz on the user's oscilloscope.
- PCM1808 VCC measured 5 V and VDD measured 3.3 V.
- No proper I2S clocks were visible, including at M5-Bus G16. This was expected
  because the then-installed independent CLK0 firmware had I2S disabled.
- The user has a two-channel FNIRSI portable scope, reporting up to 500 MS/s.
  Exact model/analog bandwidth is not known; sample rate alone is not bandwidth.
- BS170s remain absent, per the ongoing bench setup.

## Firmware changes

Separate `sdkconfig.i2s-diag.defaults` / `sdkconfig.i2s-diag` /
`build-i2s-diag` profile; prior CLK0 scope and mock profiles remain available.
The new real-board diagnostic:

1. Raises G48 and holds G47 HIGH, then runs Si5351 register/PLL checks.
2. Verifies all Si5351 outputs disabled (register 3 = 0xFF), including CLK0.
3. Starts I2S1 master RX on MCLK G16, BCLK G45, LRCK G3 and DIN G4 with the
   existing stereo Philips 32-bit slot configuration and 24-bit ADC payload.
4. Discards 48,000 startup frames (one nominal second).
5. Continuously drains the ADC, reporting raw first/last words, signed-24
   min/max/mean, nonzero-padding counts and consecutive-word changes for
   each 48,000-frame window. The first eight frames are also dumped once.
6. Leaves clocks and power on for flat/padding anomalies; these are warnings,
   not ADC PASS claims. Actual API/transport failures still clean up and request
   power off. Diagnostic mode cannot fall through to the CLK0 carrier path.

The logging harness does not guarantee lossless frame continuity; UART log
latency can consume DMA buffering. It is for electrical probing/data inspection.
No waveform frequency or voltage is measured by software in this test.

## Build and hardware verification

- ESP-IDF v5.5.1; Tab5 ESP32-P4 revision 1.3 at `/dev/cu.usbmodem101`.
- New diagnostic, existing mock-host and CLK0-only scope profiles all built.
- Only the diagnostic profile was flashed; loader hash verification passed.
- Installed diagnostic ELF SHA256 prefix: `f085f6c51`.
- `tools/i2s_diagnostic.py --tab5 /dev/cu.usbmodem101 --seconds 10` captured
  an explicit reset, confirmed the intended mode and eight sequential reports.
- All eight windows varied on both channels and had padding_nonzero=0. No
  firmware/transport error, reset loop or diagnostic anomaly was reported.
- First raw pair: `0x0007FF00 / 0xFFF9B200`, clearly not the previous constant
  `0xFFFFFF00` inference. Final-window signed values: L -6034..7710,
  mean -5; R -428..437, mean -3.
- Earlier right-channel windows included a larger transient; that is recorded
  without attributing it to a cause or treating this as analog qualification.

## Interpretation and next measurements

Live, correctly padded data now arrives. The original failure's cause is not
isolated: both the startup wait and RF clock state changed (the earlier test
kept CLK1/QSD enabled; this diagnostic disables all Si5351 outputs). Later
controlled A/B tests can separate those factors. No claim is made that a
one-second wait alone fixes the original condition.

Current expected clocks while this firmware remains powered:

| Probe point | Expected frequency | Starting timebase |
| --- | --- | --- |
| G16 / PCM1808 SCKI pin 6 | 12.288 MHz | 100 ns/div |
| G45 / PCM1808 BCK pin 8 | 3.072 MHz | 500 ns/div |
| G3 / PCM1808 LRCK pin 7 | 48 kHz | 5 us/div |

Use high-impedance x10 probes, short board-ground connections, DC coupling,
and start near 1 V/div with a rising-edge trigger around 1.5 V. Check the clock
at the ADC end as well as the M5-Bus. Then compare DOUT (ADC pin 9 / G4) with
BCK/LRCK. CLK0 is deliberately OFF. G48/G47 remain HIGH and I2S is left on
after the serial capture closes. No further resets were performed after this
capture, allowing uninterrupted manual probing.
