# Real RF board / CLK0 scope bring-up — 2026-09-18

Result: firmware implemented, built and flashed, but **hardware validation is
blocked by no I2C response from the Si5351 at 0x60**. No carrier is running.
The real PCM1808 test and new carrier programming have not yet been reached.

## Setup and source

- Tab5 ESP32-P4 revision 1.3, `/dev/cu.usbmodem101`.
- Real RF daughter board; user reports no BS170s installed.
- Board mapping checked against all five pages of Barb's *TAB5 DX Building and
  Programming port Info.pdf* (September 2026): G48 HIGH = RF main power enabled;
  G47 HIGH = RX selected / TX off. G48 is not a complementary TX-control pin.
- Same internal I2C GPIO31/32 and PCM1808 I2S GPIO16/45/3/4 as earlier tests.
- The PDF shows a separate battery-positive lead. Whether that supply or the
  DC-input supply is present on the user's assembly is not yet confirmed.

## Changes

- Separate `sdkconfig.scope.defaults` profile and `build-scope` directory;
  existing mock configuration remains intact. Real-board mode cannot select
  the mock pattern or mock TX-clock-mask test.
- Preload G48 LOW and G47 HIGH, configure outputs, then enable G48 with a
  200 ms startup interval. All fatal errors request clocks off and G48 LOW.
- After existing Si5351 checks and real ADC capture succeed, disable the
  I2S clocks and program CLK0 to nominal 14.075 MHz with PLLA 788.2 MHz / 56.
  Spread spectrum is off, only CLK0 is enabled, and G47 remains HIGH.
- The helper checks the known nominal-26-MHz register vectors, persistent
  register readback, PLL-reset self-clear and PLLA lock. Physical output
  frequency/amplitude still require the user's oscilloscope.
- This is a BS170s-absent scope build, not a transmitter: no LPF interlock or
  TX sequencing is implemented. It repeats on every boot; replace the build
  before installing the PA transistors.
- Added a single-board serial runner. It drains USB startup output before
  explicit resets and captures failure cleanup before closing the port.

## Verification performed

ESP-IDF v5.5.1 built both the real-board scope profile and existing mock host
profile successfully. Only the scope profile was flashed to the Tab5; loader
hash verification passed. Final installed ELF SHA256 prefix: `a7672f18a`.

The final controlled-reset transcript shows:

1. Firmware sets G48 HIGH and G47 HIGH, then probes for up to two seconds.
2. Address 0x60 never acknowledges.
3. An address-only scan on GPIO31/32 sees `0x10`, `0x32`, `0x40`, `0x41`,
   `0x43`, `0x44`, and `0x68`, demonstrating other devices can communicate on
   the internal bus. It does not establish the RF board's supply voltage.
4. Error `ESP_ERR_NOT_FOUND` stops the test. The output-disable I2C attempt
   also receives NACK, then firmware sets G48 LOW and keeps G47 HIGH.

No change to reference frequency or PLL calculations can fix an absent I2C
address. Next hardware checks: RF supply/battery lead and polarity, header
seating/orientation, local 3.3 V, and Si5351 SDA/SCL connections. G48 is turned
off after a failed startup, so a later static switched-rail reading of zero
would be expected; reset retries the startup after a connection is corrected.
